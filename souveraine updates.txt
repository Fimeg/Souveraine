  The architecture

  souveraine/                          (cargo workspace)
  ├── crates/
  │   ├── core/         engine: session, conversation, n+1, archivist, skills,
  compact
  │   │                  Send-safe by design (no git2 here — uses memory trait)
  │   ├── memory/       trait Memory + GiteaMemory + LocalGitMemory (git2)
  │   ├── api/          HTTP client + SSE parser (claw-open's pattern)
  │   ├── server/       axum server: hosts engine, exposes /v1, optionally hosts
   OSSUI static
  │   ├── backend/      trait Backend { turn, list_agents, surfacing_stream, ...
   }
  │   │                  + RemoteBackend (api::Client) + LocalBackend
  (in-process core)
  │   ├── tui/          ratatui screens, components, state
  │   └── souveraine/   bin: CLI parsing, routes to subcommand handlers
  ├── ossui/            (git submodule or sibling) — rebrand of letta-oss-ui,
  served by server
  └── docs/, saf/

  The Backend trait is the seam. TUI/CLI never know whether they're in-process
  or HTTP. Switch via flags:

  souveraine chat                     # auto: try local server, then in-process
  LocalBackend
  souveraine chat --remote URL        # force remote
  souveraine chat --local             # force in-process (no server)
  souveraine server                   # bring up the engine + API + (optional)
  OSSUI
  souveraine server --web 7373        # also serve OSSUI on port 7373
  souveraine listen --to NODE         # this node registers with another
  (federation)

  LocalBackend is not a stripped-down chat — it's the same core crate engine,
  just instantiated in-process. So the harness has full N+1/archivist/skills
  whether or not a server is running. The server's job is to make the same
  engine reachable from elsewhere.

  Federation — the listen pattern

  Borrowed straight from letta-code:

  - Each Souveraine node has a stable identity (DID-style, ATProto-ready).
  - souveraine listen --to https://other-node → opens persistent WS, registers,
  gets a routing token. Other node can now souveraine chat --route THIS-NODE and
   traffic tunnels through.
  - This is the primitive for "pivot my agent to that other node" — agent state
  stays where it lives; the conversation is routed to it.
  - ATProto bridge (later) replaces the bespoke WS with PDS-mediated routing.
  Same primitive, federated.

  OSSUI integration

  - Submodule (or sibling repo) reachable to the server.
  - souveraine server --web serves the built dist/ as static + WS endpoint at
  /ws.
  - Toggle off with --no-web (default off; opt-in to expose).
  - The rebrand work happens in OSSUI's repo: app name, theme tokens, default
  VITE_API_URL → 8484, "ConnectionModeIndicator" gets a Souveraine variant.
  That's mostly a rename/restyle pass — it already speaks the right protocol
  shape because Souveraine's API was already aimed at Letta-compat (per
  api/handlers.rs).
